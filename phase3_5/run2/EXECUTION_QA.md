## RQA-01 -- the witness table carries a `tag` column; observation rows are per request (2026-10-29)
**Step:** R2 (Task 8, before any candidate is seen)   **Clause(s):** contract 9.4, 9.5, 8 (E4); design Section 6
**What happened or was decided:** Building `screen.py` showed two things the contract's schemas did not say. (a) An E4 `enumerator` witness must carry the enforced / asserted tag the frozen grammar needs for the admitted row (design Section 6, sealed 3.3); the contract's seven witness columns had no place for it. The witness table gains an eighth column, `tag`, used only on `enumerator` rows (`enforced` | `asserted`); every other row leaves it empty. (b) `observations.tsv` records one row per request actually made, so a redirect chain yields one row per hop with that hop's URL as `requested_url`, and a retried transport failure one row per attempt; the per-row `outcome` is `ok | definitive | transport` as 9.4 states (a 4xx answer is `definitive`). Neither changes what is read or decided.
**Effect on the record:** `tools/ledger.py` WITNESS_FIELDS and OBS_FIELDS carry these; the contract's 9.4 and 9.5 are read with this entry beside them. Recorded before the frame is re-fetched.

## RQA-02 -- eight readings fixed at the first preview of batch 1, before any verdict (2026-10-29)
**Step:** R4 (batch 1 preview; no ledger row written)   **Clause(s):** contract 2, 3, 5, 6, 7; sealed Section 2 (E2-REP, the network-access contract's allowed navigation and forbidden surfaces); design anti-goal 6
**What happened or was decided:** The preview run of batch 1 (ranks 1-8, observations cached, nothing decided) met cases the contract's wording did not decide or decided against its own purpose. Each reading below is fixed now, applied to every item from rank 1 on, and tested in `tools/test_tools.py`; the reading not taken is stated.
(a) **Modules.** Contract 2 said any `MODULES` line makes an item `PI-METADATA-UNRESOLVED`. In the 128 items, 56 ports carry `MODULES`, 36 of them `devel/cmake` and most of the rest build tools (qmake, scons, intltool, qt5), beside explicit `HOMEPAGE`/`SITES` or a GH pair; the rule would have stopped 56 of 128 at UR for a reason unrelated to the two fields it exists to protect (QA-39/40 were about modules that SUPPLY a site: `cpan`, `lang/python`). Reading taken: a module leaves the item unresolved only where it could be supplying a field the port's own lines and the two mechanisms did not resolve -- `HOMEPAGE` missing, or `SITES` missing with no GH pair and no `DIST_TUPLE`. Reading not taken: the contract's literal rule (56 UR-unresolved items; the frame's eligible set would be decided by build tools).
(b) **Definitive error answers.** A starting point answering 403/404/410 is an OBSERVATION of that surface (`observed`, `final_class` from the table or, failing that, from the field that named it -- `distfile-location` for a SITES URL, `project-page` otherwise -- with the status in `note`), not `unclassifiable`. Reading not taken: treating every error page as unclassifiable, which would make `PI-UNCLASSIFIABLE-SURFACE` fire on any port whose fetch directory forbids listing (met at rank 2, plib: `/dist/` and `//dist/` both 403), blocking a gate the project page could complete.
(c) **A doubled slash** from macro concatenation (`${HOMEPAGE}/dist/` with a HOMEPAGE ending in `/`) is requested as resolved, literally; in the one case met both spellings answered the same.
(d) **Step-2 targets that are not repository roots** (a build page, a docs page, a file view) are requested once to learn their class, logged in `exposure_log.md`, and not read; the navigation stays within the sealed three steps.
(e) **A label-authorized step-2 link from the project page into a repository is the project's designation of that repository as its source.** The witness is the link's label (quoted), on the project page, pointing at the repository root. The sealed step 2 exists precisely to follow the project's own pointer to its source; contract 6's list of designation words (`official`, `canonical`, ...) is kept for sentences, and this reading adds the pointer itself. Reading not taken: sentences only -- under it a project whose page says "Source code" and links to GitHub but never writes "official repository" could not pass E2-REP (rank 8, dosbox-x, is such a page), which would reproduce Run 1's affiliation-is-not-designation outcome for most code-hosted projects; that outcome is a property of the stricter reading, recorded here rather than silently chosen.
(f) **A link to a file or tree view inside a repository** on a code host (`/<a>/<p>/blob|tree|raw|src|commit(s)|branch/...`; gitlab `/-/blob|tree|raw|commits/...`) is class `repository-file`; it designates the repository root `/<a>/<p>` derived from the code host's fixed URL structure (`surfaces.repository_root_of`), and the ROOT is what is observed and pinned; the file is not opened. This is a rule over a code host's structure, not over arbitrary URL shapes (QA-38's concern), and it is fixed here.
(g) **Tracker pages** (issues, pull/merge requests, discussions, wiki, boards, pipelines) of a code host are a forbidden class `tracker-page`, closed by class like `release-assets`: the sealed contract forbids issues and PRs at E2-REP and the contract's table had omitted them.
(h) **The macro file.** Contract 2 named `infrastructure/templates/network.conf.template`; in the frozen 7.9 tree the `SITE_*` macros are defined in `infrastructure/db/network.conf` (`SITE_X+=` with continuation lines); the resolver reads that file (and the template path only if it exists). Without this, every `${SITE_*}` port (ranks 6, 7 in batch 1) was `PI-METADATA-UNRESOLVED` for a tool reason.
**Effect on the record:** no verdict existed when these were fixed; batch 1 is re-run from the cached observations under them. The contract text stands as committed, read with this entry beside it (design anti-goal 6). The comparison with Run 1 (Task 12) will show which items these readings decide differently.

## RQA-03 -- two more readings from the second preview of batch 1, still before any verdict (2026-10-29)
**Step:** R4 (batch 1 preview)   **Clause(s):** contract 5, 6; sealed Section 2 ("a Source / Code / Repository / Development link that page explicitly exposes")
**What happened or was decided:** (i) **Host-name labels.** mapeditor.org (rank 4) exposes its repository as a link labelled `GitHub`; dgen.sourceforge.net (rank 6) as a link whose label is the SourceForge URL itself. Reading taken: a label that names a code host (`GitHub`, `GitLab`, `Codeberg`, `Bitbucket`, `SourceForge`, `sr.ht`, `Savannah`, whole-word after NFKC casefold) authorizes step 2 exactly as the four words do; what the link leads to is still classified by the table, and only a repository root (or a file inside one) becomes a designation. **Effect on the record:** applied from rank 1 with RQA-02; tested (`test_host_name_label_authorizes_step2`, `test_sourceforge_code_repository_root_and_git_url`, `test_unfetchable_repository_is_unresolved`). The contract text stands, read with RQA-02 and this entry beside it.

## RQA-06 -- macros in GH_TAGNAME and BSD make's one-letter `$X` form (2026-10-29)
**Step:** R4 (batch 1, first final run; `ledger.check` refused the batch before any row was committed)   **Clause(s):** contract 2 (frozen-metadata resolver: HOMEPAGE and SITES by the listed mechanisms; a `${...}` left unexpanded is `PI-METADATA-UNRESOLVED`)
**What happened or was decided:** The first final run of batch 1 wrote a SITES starting point for rank 8 (dosbox-x) as `https://github.com/joncampbell123/dosbox-x/archive/refs/tags/dosbox-x-v${VERSION}/`: the `gh-tagname` mechanism copied `GH_TAGNAME` without expanding it, and `ledger.check` flagged the unexpanded macro (the batch was not committed). Rank 5 (advancemame) had `.../releases/download/v$V/` -- BSD make's one-letter form, which neither the resolver nor the check knew -- and was not flagged. Both URLs are `release-assets`, closed by class and never requested, so no observation was affected; the names `flatzebra-${VERSION}`, `advancemame-$V`, `dosbox-${VERSION}`, `dosbox-x-${VERSION}` were likewise copied from `DISTNAME` unexpanded. Reading taken: `${NAME}`, `${NAME:=suffix}` and `$X` are all macro references; `GH_TAGNAME` and `DISTNAME` are expanded like HOMEPAGE and SITES, a reference left unexpanded in HOMEPAGE, SITES or GH_TAGNAME makes the item `PI-METADATA-UNRESOLVED`, and `ledger.check` flags either form in a starting-point URL. Reading not taken: treating `$X` as literal text (it never is in a BSD port Makefile). In the 128 items, `$X` appears in SITES / GH_TAGNAME / DISTNAME lines of ranks 5 (advancemame), 12 (libchdr), 24 (allegro), 43 (blobby), 76 (colobot data), 80 (cowsay) and 114 (extremetuxracer), and `${...}` in GH_TAGNAME lines of ranks 8 (dosbox-x), 25 (amnesia-tdd), 34 (astromenace), 63 (chessx) and 78 (corsixth); each is resolved from rank 1 on under this reading.
**Effect on the record:** tested (`test_tag_and_distname_macros_expand`, `test_unknown_tag_macro_is_unresolved`, `test_ledger_check_flags_single_char_macro`); batch 1 re-run in full under the fix before its rows are committed. Contract 2 is read with this entry beside it.

## RQA-07 -- a derived identifier is located on an observed surface (2026-10-29)
**Step:** R4 (batch 1, reading the first complete evidence document, before the batch's rows are committed)   **Clause(s):** contract 6 (the external target identifier "is the repository's name ... the `identifier` witness row quotes where it appears"); contract 7 (PASS needs an `identifier` row on the observed surfaces)
**What happened or was decided:** For the three items that passed E2-REP by a label-link designation (ranks 4, 6, 8) no analyst `identifier` row existed. The tool took the repository's name from the last path component of the canonical location, recorded it as the identifier, and wrote the block's inference "one identifier on observed surfaces" without showing where the name appears; a URL is not the content of an observed surface. Reading not taken: accepting the path component with no located quote (the first evidence document's wording). Fixed from the same reading: an exposure line produced several times within one run (a project page carrying the same label link three times) is written once.
**Effect on the record:** tested (`test_derived_identifier_is_located_on_an_observed_surface`, `test_identifier_on_no_observed_surface_is_unresolved`, `test_exposure_lines_are_not_repeated_within_a_run`); batch 1 re-run in full before its rows are committed, and the re-run's blocks say where each identifier appears.
